# 🗣️ 丹尼爾的評論

> 「**你懂我的痛，但你還沒證明你能治好它，也還沒跟我講清楚這藥多少錢、有沒有副作用。**」

## 結論先講：現在不直接買，但會認真談 PoC

## 一、打中我心坎的部分

- **「知識留在系統裡，不會離職」** — 這是我最痛的事。廠裡那台影像辨識機器、那台 mini-PC，設定的同事離職了，現在沒人敢動，怕動了掛掉沒人會修。光這點就值得坐下來聽。
- **兩軸命名** — 我們公司也有編號災難：「3 號機」到底是實體還是 VM、上面跑什麼，三個月後沒人說得清。拆成「本體」＋「部署方式」很乾淨，是少數「不是為了賣而造出來」的設計。
- **「不用學 k3s」** — 我公司沒有人力養專職 SRE，能用中文叫 agent 查問題，等於省半個人力。

## 二、我會打問號的 5 個地方

1. **AI agent 是幫手還是新的黑盒子？** 只是把複雜性從 k3s 換成 agent — 它壞了誰修？判斷錯了誰負責？
2. **能力矩陣一半是藍圖不是現況** — 已實作的都是 VM；Jetson 真機「已下單未驗證」、實體機全是藍圖。我們現況就是一堆實體機，你卻叫我用「我沒有的場景」評估你。
3. **定價、SLA、客戶案例全部空白** — 對要掏錢的中小企業是致命的。我不會為沒 SLA、沒 reference 的東西簽約。
4. **Vendor lock-in** — k3s + KubeEdge + Ansible + Tailscale + Hermes 綁一串，我未來想走成本多高？信任模型那段是賣方視角，不是幫我解決「不爽了怎麼走」。
5. **單點風險** — Phase 0 一台主機跑控制面，HA 是 TODO 不是 done。便宜但單點 vs 貴但穩，我寧可知道代價再選。

## 三、我的評估邏輯（3 問）

- **能不能取代「再請一個人」？** 總成本（授權＋硬體＋學習時間）< 台南維運工程師月薪 4-6 萬就有價值。但前提是它真的能像個「人」一樣被使喚。
- **會不會變成新負債？** 導入後 team 裡有沒有人能接？還是從此被賣方綁死？我們公司規模小，最怕的不是貴，是「斷不了」。
- **能先小範圍試嗎？** 挑最不痛的場景（一台 VM 跑 docker 的服務）先跑三個月，看 agent 是不是真的聽得懂人話、SOP 是不是真的能交接。

## 四、我想問賣方的 5 個問題

1. 你們在**真實混合實體機＋邊緣裝置**環境跑過多久？不是 VM 模擬，是真的 Jetson 在產線上跑幾個月、斷網了會怎樣。藍圖的部分我不買單，我要看到現況。
2. agent 出錯、或你們公司倒了，**我的人能不能接手**？SOP 和維運知識是以什麼格式存在我手上？是不是隨時可以帶走、自己維護？
3. **定價和 SLA 給具體數字** — 中小企業平價入門是多少？單台主機掛掉，多久能恢復？這兩個問題答不出來，後面都不用談。
4. 綁死 Tailscale，**我未來有多少自主權**？roadmap 寫 Headscale 取代 SaaS，我現在選你，三個月後架構又改？我的資料、我的節點在哪、誰看得到？
5. **最小可行 PoC 怎麼算錢、多久上線**？我要明確試用範圍和驗收標準（如「一台 VM＋docker 服務，agent 能在 30 天內穩定處理 X 次故障定位」）。

## 五、總體判斷：現在不買，但會認真談 PoC

我會不會買？**現在這個狀態，不會直接買。** 不是因為提案寫得不好 — 相反的，它的 UX 承諾（兩軸命名、知識留存、自然語言維運）是我這幾年看過少數真的懂中小企業痛的設計。但問題是：**我最需要的場景（實體機＋邊緣裝置真機）它還是藍圖，而我最在意的東西（價錢、SLA、能不能脫身）它一個字都沒寫。**

所以我的決定是：**不簽約，但值得給一個 PoC 機會。** 如果三個月內它能在我們一台真實的邊緣裝置上跑起來、真的讓我 team 裡最不懂 k8s 的那個同事用中文把問題查出來，而且把維運知識留在我們手上 — 那這東西我會認真往上簽。
